What it won't let you do

Each of these would break a server or leave one open. The builder stops it before a line is written, and tells you why.

Put two things on one port

80 and 443, DNS on 53, 3000, 8080, 9090, 9100 and 3306. Pick one and its rivals grey out.

apache: Can't go with nginx: both want ports 80 and 443.

Use a circuit on an untested distro

A circuit is offered only on the distributions its own CI tests.

zeek: Not tested on Rocky Linux 10 yet.

Type a password into the page

Secrets become variables in variables.tf. You set them in your shell; main.tf only points at them.

export TF_VAR_valkey_password='...'

Forget what a circuit needs

Pick Infisical and PostgreSQL and Valkey come along, wired with the role, database and URLs it expects.

depends_on = [module.postgres, module.valkey]

Open more than you use

With the firewall picked, it opens only what your picks listen on. LAN-only ports like Samba's 445 open to a network you name, or stay shut.

{ port = "80/tcp" },

Run unpinned or unofficial code

Only official circuits, each pinned to its release. No raw HCL: every value you type is escaped by one tested function.

source = "github.com/conn3xorg/circuit-nginx?ref=v0.1.0"
